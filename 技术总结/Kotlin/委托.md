Kotlin 的**委托（Delegation）​**是一种通过将对象的部分或全部功能委托给另一个对象来实现代码复用和解耦的设计模式。它通过 `by` 关键字实现，核心思想是“**我委托你来做**”，避免重复实现通用逻辑。以下从**核心概念、实现原理、类型与考点**三方面详细解析：

#### 一、委托的核心概念

委托的本质是**对象间的职责转移**​：
- ​**被委托类（`Delegate`）​**​：负责实际执行委托的功能（实现具体逻辑）；
- ​**委托类（`Delegator`）​**​：声明需要委托的功能，但自身不实现，而是将职责交给 `delegate` 对象。

Kotlin 通过 `by` 关键字声明委托关系，编译器会自动生成桥接代码，将被委托类的方法调用转发给委托对象。

#### 二、委托的实现原理
Kotlin 的委托机制在编译时通过**静态代理**实现，具体分为两种场景：
##### 1. ​**类委托（Implementing Interfaces by Delegation）​**​
当委托类需要实现某个接口时，通过 `by` 关键字将接口的实现委托给另一个对象（需实现该接口）。

​**编译器行为**​：
- 生成一个匿名类（委托类的子类），实现被委托的接口；
- 在匿名类中，所有接口方法的调用会被转发给委托对象（`delegate`）。

​**示例**​：
```kotlin
interface Printer {
    fun print(message: String)
}

class ConsolePrinter : Printer {
    override fun print(message: String) {
        println("Console: $message")
    }
}

// 委托类：通过 by 将 Printer 接口的实现委托给 ConsolePrinter
class DocumentPrinter(private val delegate: Printer) : Printer by delegate

// 使用
val printer = DocumentPrinter(ConsolePrinter())
printer.print("Hello") // 输出 "Console: Hello"（调用被委托对象的实现）
```

##### 2. ​**属性委托（Property Delegation）​**​
属性委托用于简化属性的 `getter` 和 `setter` 实现，将属性的读写逻辑委托给一个委托对象（需实现 `ReadOnlyProperty` 或 `ReadWriteProperty` 接口）。

​**核心接口**​：
- `ReadOnlyProperty<T, V>`：仅定义 `getValue()`（用于只读属性）；
- `ReadWriteProperty<T, V>`：定义 `getValue()` 和 `setValue()`（用于可变属性）。

​**编译器行为**​：
- 为属性生成 `getter` 和 `setter`，内部调用委托对象的 `getValue()` 或 `setValue()`；
- 委托对象的生命周期与属性绑定（通常在委托类的构造函数中初始化）。

​**示例（自定义属性委托）​**​：
```kotlin
// 自定义只读属性委托（实现 ReadOnlyProperty）
class LazyInitDelegate<T>(private val initializer: () -> T) : ReadOnlyProperty<Any?, T> {
    private var value: T? = null

    override fun getValue(thisRef: Any?, property: KProperty<*>): T {
        if (value == null) {
            value = initializer() // 延迟初始化
        }
        return value!!
    }
}

// 使用属性委托
class MyClass {
    val lazyValue: String by LazyInitDelegate { 
        println("Initializing...") 
        "Hello Kotlin" 
    }
}

// 测试
val obj = MyClass()
println(obj.lazyValue) // 输出 "Initializing..." 和 "Hello Kotlin"（仅初始化一次）
```

#### 三、Kotlin标准委托（内置委托）
Kotlin 标准库提供了多个内置委托，用于解决常见场景问题，是面试的高频考点：
##### 1. ​`lazy` 委托（延迟初始化）​**​
- ​**作用**​：实现属性的延迟初始化（仅在首次访问时初始化），线程安全（默认使用 `SynchronizedLazyImpl`）。
- ​**适用场景**​：初始化成本高（如 IO、复杂计算）的属性，避免类加载时浪费资源。

​**示例**​：
```kotlin
class HeavyObject {
    init { println("HeavyObject initialized") }
}

class MyClass {
    val heavyObj: HeavyObject by lazy { HeavyObject() } // 首次访问时初始化
}

// 测试
val obj = MyClass() // 未初始化 HeavyObject
obj.heavyObj // 输出 "HeavyObject initialized"（首次访问时初始化）
```

##### 2. ​`observable` 委托（属性监听）​**​
- ​**作用**​：监听属性的修改（`setter` 被调用时触发回调），适用于需要响应属性变化的场景（如 MVVM 中的数据绑定）。
- ​**参数**​：初始值、回调函数（`onChange: (oldValue: T, newValue: T) -> Unit`）。

​**示例**​：
```kotlin
class User {
    var name: String by Delegates.observable("Unknown") { 
        _, old, new -> 
        println("Name changed from $old to $new") 
    }
}

// 测试
val user = User()
user.name = "Alice" // 输出 "Name changed from Unknown to Alice"
user.name = "Bob"   // 输出 "Name changed from Alice to Bob"
```

##### 3. ​`vetoable` 委托（属性修改拦截）​**​
- ​**作用**​：拦截属性的修改操作，根据条件决定是否允许修改（类似“否决权”）。
- ​**参数**​：初始值、回调函数（`onSet: (oldValue: T, newValue: T) -> Boolean`，返回 `false` 则拒绝修改）。

​**示例**
```kotlin
class Account {
    var balance: Double by Delegates.vetoable(0.0) { 
        _, old, new -> 
        if (new < 0) { 
            println("Balance cannot be negative") 
            false // 拒绝修改 
        } else { 
            true // 允许修改 
        } 
    }
}

// 测试
val account = Account()
account.balance = 100.0 // 允许修改（输出无）
account.balance = -50.0 // 拒绝修改（输出 "Balance cannot be negative"）
```

##### 4. ​**`map` 委托（Map 属性映射）​**​
- ​**作用**​：将类的属性映射到 `Map` 中（键为属性名，值为属性值），适用于动态属性管理（如解析 `JSON` 或配置）。
- ​**实现**​：通过 `Map` 的 `get` 和 `put` 方法实现 `getValue` 和 `setValue`。

​**示例**​：
```kotlin
class User(map: Map<String, Any>) {
    val name: String by map // 从 map 中获取 "name" 对应的值
    val age: Int by map    // 从 map 中获取 "age" 对应的值
}

// 测试
val userMap = mapOf("name" to "Alice", "age" to 25)
val user = User(userMap)
println(user.name) // 输出 "Alice"
println(user.age)  // 输出 25
```

#### 四、委托的核心考点
在 Kotlin 面试中，委托的高频考点集中在**实现原理、标准委托的使用场景、委托与继承的区别**等。以下是关键问题及解答：

##### 1. ​**委托与继承的区别是什么？​**​
- ​**继承**​：通过 `:` 符号继承父类的属性和方法（子类是父类的“类型扩展”）；
- ​**委托**​：通过 `by` 关键字将功能委托给另一个对象（委托类与被委托类是“协作关系”，无继承关系）。

​**示例对比**​：
```kotlin
// 继承：子类继承父类方法
open class Animal {
    open fun sound() = "Unknown"
}
class Dog : Animal() {
    override fun sound() = "Woof"
}

// 委托：委托类将功能委托给另一个对象
interface SoundMaker {
    fun sound(): String
}
class DogSound : SoundMaker {
    override fun sound() = "Woof"
}
class Dog(delegate: SoundMaker) : SoundMaker by delegate
```
##### 2. ​**`by` 关键字在委托中的作用是什么？​**​
`by` 关键字用于声明委托关系，告知编译器“该属性/接口的实现由 `delegate` 对象提供”。编译器会根据委托类型（类委托/属性委托）生成相应的桥接代码，将被委托类的方法调用转发给 `delegate` 对象。
##### 3. ​**属性委托的 `getter` 和 `setter` 如何被委托？​**​
- 对于 `ReadOnlyProperty` 委托，编译器仅生成 `getter`，调用 `delegate.getValue()`；
- 对于 `ReadWriteProperty` 委托，编译器生成 `getter`（调用 `delegate.getValue()`）和 `setter`（调用 `delegate.setValue()`）。
##### 4. ​**`lazy` 委托的线程安全性如何保证？​**​
Kotlin 的 `lazy` 委托默认使用 `SynchronizedLazyImpl`（线程安全），通过 `synchronized` 关键字保证多线程下仅初始化一次。若需非线程安全版本，可使用 `LazyThreadSafetyMode.NONE`（不推荐）。
##### 5. ​**自定义属性委托需要实现哪些接口？​**​
- 只读属性委托需实现 `ReadOnlyProperty<T, V>`（仅需 `getValue()`）；
- 可变属性委托需实现 `ReadWriteProperty<T, V>`（需 `getValue()` 和 `setValue()`）。
##### 6. ​**委托对象的生命周期如何管理？​**​
委托对象的生命周期与委托类的实例绑定（通常在委托类的构造函数中初始化）。若委托对象需要更长的生命周期（如单例），需注意内存泄漏问题（避免委托类持有长生命周期对象的强引用）。

#### 五、总结
Kotlin 委托的核心是**通过 `by` 关键字将功能委托给其他对象**，实现代码复用和解耦。其设计思想符合“组合优于继承”的原则，适用于延迟初始化、属性监听、动态属性管理等场景。面试中需重点掌握：

- 委托的两种类型（类委托、属性委托）；
- 标准委托（`lazy`、`observable`、`vetoable`）的使用场景；
- `by` 关键字的作用与编译器行为；
- 委托与继承的区别及适用场景。
