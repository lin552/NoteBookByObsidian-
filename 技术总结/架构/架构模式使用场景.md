|​**维度**​|​**MVC**​|​**MVP**​|​**MVVM**​|​**MVI**​|
|---|---|---|---|---|
|​**核心思想**​|经典三层架构，通过 Controller 协调 Model 和 View 的交互。|从 MVC 演变，通过 Presenter 解耦 View 和 Model，强调逻辑与界面分离。|数据驱动，通过 ViewModel 和数据绑定实现 View 与 Model 的自动同步。|单向数据流，以不可变状态（ViewState）为核心，通过 Intent 触发状态变更。|
|​**数据流向**​|单向：用户 → Controller → Model → View → 用户。|单向：用户 → View → Presenter → Model → View。|双向：View ↔ ViewModel ↔ Model（通过数据绑定）。|单向循环：Intent → ViewModel → Model → ViewState → View。|
|​**组件职责**​|- ​**Model**​：数据与业务逻辑<br>- ​**View**​：界面展示<br>- ​**Controller**​：协调交互|- ​**Model**​：数据与业务逻辑<br>- ​**View**​：纯界面<br>- ​**Presenter**​：逻辑处理与界面更新|- ​**Model**​：数据与业务逻辑<br>- ​**View**​：界面展示<br>- ​**ViewModel**​：状态管理与数据绑定|- ​**Model**​：不可变状态<br>- ​**View**​：界面渲染<br>- ​**Intent**​：用户意图<br>- ​**ViewModel**​：状态处理|
|​**适用场景**​|- 传统 Web 应用（如 Rails）<br>- 小型桌面应用<br>- 快速原型开发|- 复杂 UI 逻辑（如 Android 早期）<br>- 需严格分离界面与逻辑的项目|- 现代前端框架（Vue/Angular）<br>- 动态交互的 SPA<br>- 跨平台开发（WPF）|- 复杂状态管理（如实时聊天）<br>- 响应式编程项目<br>- 企业级应用|
|​**优点**​|- 简单易上手<br>- 分层明确<br>- 快速开发|- 强制解耦 View 和 Model<br>- Presenter 可独立测试<br>- 适合中型项目|- 数据绑定减少手动 DOM 操作<br>- 高代码复用性<br>- 支持声明式 UI|- 严格单向数据流，状态可预测<br>- 易调试和测试<br>- 高可维护性|
|​**缺点**​|- Controller 易臃肿<br>- View 和 Model 间接耦合<br>- 测试难度较高|- Presenter 接口冗余<br>- 手动同步数据到 View<br>- 代码量增加|- 数据绑定调试复杂<br>- 性能可能受绑定机制影响<br>- 大型项目维护成本高|- 实现复杂度高（需处理不可变状态）<br>- 学习曲线陡峭<br>- 内存开销较大|
|​**学习曲线**​|低|中等|中等（需熟悉数据绑定框架）|高（需响应式编程经验）|
|​**测试难度**​|高（Controller 与 View 耦合）|中等（Presenter 可测，View 需模拟）|低（ViewModel 独立，View 可模拟）|高（需模拟 Intent 和状态流）|
|​**性能**​|中等|中等|高（数据绑定优化）|中等（依赖响应式库优化）|
|​**团队经验要求**​|适合熟悉分层架构的团队|需要一定 MVVM 基础|需熟悉数据绑定框架（如 Vue/React）|需响应式编程经验（如 RxJava/Kotlin 协程）|
|​**典型框架/工具**|Ruby on Rails、Spring MVC、Backbone.js|Android MVP、WinForms|Vue.js、Angular、Jetpack Compose|Kotlin MVI、RxJava、Bloc Pattern|`
