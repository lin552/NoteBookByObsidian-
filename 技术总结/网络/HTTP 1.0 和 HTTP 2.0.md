HTTP/1.0 和 HTTP/2.0 是 Web 协议发展的两个关键版本，其核心区别体现在**连接管理、传输效率、协议设计**等方面。以下是两者的重大区别及技术解析：

#### 一、连接管理：从短连接到多路复用

##### 1. ​**HTTP/1.0 的短连接与队头阻塞**​
- ​**短连接**​：每个请求需独立建立 `TCP` 连接，响应完成后立即关闭，导致频繁的 `TCP` 三次握手和四次挥手，增加延迟和资源消耗
- ​**队头阻塞**​：同一连接内请求必须按顺序处理，若前一个请求未完成，后续请求会被阻塞，无法并发
##### 2. ​**HTTP/2.0 的多路复用与持久连接**​
- ​**多路复用**​：单个 `TCP` 连接可同时处理多个请求（通过流 ID 区分），请求可交错发送和接收，彻底消除队头阻塞
- ​**持久连接**​：默认保持连接复用，减少 `TCP` 握手开销，提升带宽利用率
#### 二、数据传输：文本格式 vs 二进制分帧
##### 1. ​**HTTP/1.0 的文本协议**​
- 请求和响应以纯文本形式传输（如 `GET /index.html HTTP/1.0`），解析效率低，易因格式错误导致通信失败
##### 2. ​**HTTP/2.0 的二进制分帧**​
- 数据拆分为二进制帧（如头部帧、数据帧），通过流 ID 组装，解析更高效且支持乱序传输
- ​**优势**​：减少解析时间，支持更复杂的协议扩展（如流优先级）。
#### 三、头部优化：冗余重复 vs 压缩复用
##### 1. ​**HTTP/1.0 的头部冗余**​
- 每个请求需完整发送头部（如 `User-Agent`、`Cookie`），重复数据占用大量带宽
##### 2. ​**HTTP/2.0 的 `HPACK` 压缩**​
- 使用静态表（预定义常用头部）和动态表（运行时缓存）压缩头部，减少 50%-90% 的传输量
- ​**示例**​：首次发送完整头部后，后续请求仅需发送差异字段的索引值。
#### 四、服务器推送：被动响应 vs 主动推送
##### 1. ​**HTTP/1.0 的被动模型**​
- 服务器仅响应客户端显式请求，无法预判资源需求，导致多次请求（如 HTML 加载后需单独请求 `CSS/JS`）
##### 2. ​**HTTP/2.0 的服务器推送**​
- 服务器可主动推送关联资源（如 HTML 引用的 `CSS/JS`），减少客户端请求次数，提升首屏渲染速度
- ​**限制**​：需避免过度推送（如缓存未过期资源），可通过 `Cache-Control: no-push` 禁用。
#### 五、性能优化：优先级与流量控制

##### 1. ​**HTTP/1.0 的简单调度**​
- 请求按顺序处理，无法调整优先级（如图片加载可能阻塞关键 CSS）
##### 2. ​**HTTP/2.0 的流优先级与流量控制**​
- ​**优先级设置**​：客户端可为流分配权重（如高优先级传输 HTML，低优先级传输图片），优化资源加载顺序
- ​**流量控制**​：基于窗口机制动态调整数据传输速率，防止接收方过载（如弱网环境下限制大文件传输）

#### 六、安全性增强
- **HTTP/1.0**​：默认不加密，依赖 `HTTPS` 实现安全传输，但协议层无强制要求。
- ​**HTTP/2.0**​：强制使用 `TLS 1.2+` 加密（RFC 7540 规定），提升数据传输安全性

#### 七、性能对比与适用场景
| **指标**​     | ​**HTTP/1.0**​   | ​**HTTP/2.0**​ |
| ----------- | ---------------- | -------------- |
| ​**连接数**​   | 每个域名 6 连接（浏览器限制） | 单连接多路复用        |
| ​**延迟**​    | 高（频繁握手、队头阻塞）     | 低（持久连接、并行处理）   |
| ​**带宽利用率**​ | 低（冗余头部、串行传输）     | 高（压缩头部、并行传输）   |
| ​**适用场景**​  | 简单页面、低并发请求       | 复杂页面、高并发资源加载   |
#### 八、总结：HTTP/2.0 的核心优势
1. **消除队头阻塞**​：多路复用允许并行处理请求，提升吞吐量。
2. ​**高效传输**​：二进制分帧和头部压缩减少网络开销。
3. ​**主动推送**​：预加载资源，加速页面渲染。
4. ​**智能调度**​：优先级和流量控制优化资源分配。
