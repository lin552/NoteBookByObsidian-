#### 一、并发环境下错误
##### 1）SQLite数据库锁定错误
1️⃣ 错误表现
```java
android.database.sqlite.SQLiteDatabaseLockedException: 
database is locked (code 5 SQLITE_BUSY)
```
2️⃣ 产生原因
```java
// 线程1：开始写事务
database.beginTransaction();
database.execSQL("UPDATE users SET name='张三' WHERE id=1");
// 还没结束事务...

// 线程2：同时尝试访问数据库
Cursor cursor = database.query("SELECT * FROM users"); // 这里会抛异常！
```
##### 2)连接状态错误
1️⃣ 错误表现
```java
java.lang.IllegalStateException: attempt to re-open an already-closed object: SQLiteDatabase
```
2️⃣ 产品原因
```java
// 线程1：关闭数据库连接
database.close();

// 线程2：不知道连接已关闭，继续使用
Cursor cursor = database.rawQuery("SELECT * FROM table", null); // 崩溃！
```
##### 3)数据不一致错误
###### 脏读（Dirty Read）
```java
// 线程1：准备更新数据但没提交
database.beginTransaction();
database.execSQL("UPDATE account SET balance=balance-100 WHERE id=1");

// 线程2：读取到未提交的数据（脏数据）
Cursor cursor = database.rawQuery("SELECT balance FROM account WHERE id=1", null);
// 可能读到错误的余额

// 线程1：回滚事务
database.endTransaction(); // 回滚，刚才的更新无效
```
###### 不可重复读（Non-repeatable Read）
```java
// 线程1：第一次读取
Cursor cursor1 = database.rawQuery("SELECT * FROM orders WHERE user_id=1", null);
List<Order> orders1 = parseOrders(cursor1);

// 线程2：在中间修改了数据
database.execSQL("DELETE FROM orders WHERE user_id=1 AND id=100");

// 线程1：第二次读取，结果不一样了
Cursor cursor2 = database.rawQuery("SELECT * FROM orders WHERE user_id=1", null);
List<Order> orders2 = parseOrders(cursor2);
// orders1.size() != orders2.size()，在同一个事务中出现了不一致
```
###### 幻读（Phantom Read）
```java
// 线程1：查询数量
Cursor countCursor = database.rawQuery("SELECT COUNT(*) FROM products WHERE price>100", null);
int count1 = getCount(countCursor);

// 线程2：插入了新的符合条件的数据
database.execSQL("INSERT INTO products (name, price) VALUES ('手机', 200)");

// 线程1：再次查询，数量变了
Cursor countCursor2 = database.rawQuery("SELECT COUNT(*) FROM products WHERE price>100", null);
int count2 = getCount(countCursor2);
// count2 > count1，出现了"幻影"记录
```
##### 4)死锁 （Deadlock）
1️⃣ 错误表现
```java
// 应用卡住，ANR（Application Not Responding）
```
2️⃣ 产生原因
```java
// 线程1：先锁表A，再要锁表B
synchronized(tableA) {
    // ... 操作表A
    synchronized(tableB) {  // 等待线程2释放tableB
        // ... 操作表B
    }
}

// 线程2：先锁表B，再要锁表A  
synchronized(tableB) {
    // ... 操作表B
    synchronized(tableA) {  // 等待线程1释放tableA，形成死锁！
        // ... 操作表A
    }
}
```
##### 5)内存和性能问题
###### 连接池耗尽
```java
// 每个线程都创建自己的数据库连接
for (int i = 0; i < 1000; i++) {
    new Thread(() -> {
        SQLiteDatabase db = openDatabase(); // 创建新连接
        // ... 使用数据库
        // 忘记关闭连接！
    }).start();
}
// 系统打开文件数超限，无法创建新连接
```
###### 内存泄露
```java
// 持有数据库连接引用不释放
public class BadManager {
    private SQLiteDatabase database; // 静态变量持有连接
    
    public void init() {
        database = openDatabase(); // 永远不关闭
    }
}
// 导致数据库连接一直占用内存，最终OOM
```
