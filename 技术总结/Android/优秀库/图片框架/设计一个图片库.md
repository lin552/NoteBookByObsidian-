在 Android 中自行设计一个图片加载框架（类似 Glide、Picasso）需要综合考虑**性能、内存管理、兼容性、扩展性**等多方面因素。以下是设计时需重点关注的核心要点，结合实际开发中的常见问题和解决方案展开说明。

#### 一、架构分层设计（解耦与可维护性）

图片加载框架的核心功能可拆分为多个独立模块，通过分层降低耦合，方便后续扩展和维护。典型分层如下：

| 层级          | 职责                                  | 关键组件/接口                                 |
| ----------- | ----------------------------------- | --------------------------------------- |
| ​**资源管理层**​ | 统一管理图片来源（网络、本地文件、资源文件、Asset 等）      | `DataSource`接口（区分网络/本地）                 |
| ​**缓存层**​   | 内存缓存（快速读取）、磁盘缓存（持久化存储）              | `MemoryCache`、`DiskCache`接口             |
| ​**加载层**​   | 执行具体加载逻辑（网络请求、磁盘读取、图片解码）            | `Loader`接口（如 `HttpLoader`、`FileLoader`） |
| ​**处理层**​   | 图片变换（裁剪、缩放、滤镜等）、格式转换（WebP → Bitmap） | `Transformer`接口                         |
| ​**调度层**​   | 任务调度（优先级、并发控制、生命周期绑定）               | `Scheduler`（线程池管理）                      |
| ​**显示层**​   | 图片渲染到 View（处理 View 复用、请求取消）         | `ImageViewTarget`（绑定 View）              |
#### 二、内存管理（避免`OOM`与性能损耗）
内存是Android应用的核心资源，图片加载框架的内存管理直接影响应用的稳定性和体验。需重点关注以下几点：
##### 1.内存缓存策略（`LRU`为核心）
- **实现方式**​：使用 `LruResourceCache`（基于 `LRU` 算法），缓存键（Key）需唯一标识图片（如 URL + 尺寸 + 变换参数）。
- **容量控制**​：根据设备内存动态计算缓存大小（如 `Runtime.getRuntime().maxMemory() / 8`），避免占用过多内存。
- ​**弱引用优化**​：对正在加载的图片使用 `WeakReference`持有，防止 View 被回收时图片仍被强引用导致 `OOM`。
##### 2.图片尺寸适配（关键防`OOM`手段）
•**按需解码**​：加载网络或本地图片时，先获取目标 View 的宽高（通过 `ViewTreeObserver`监听布局完成），计算所需采样率（`inSampleSize`），避免加载原图。
```java
BitmapFactory.Options options = new BitmapFactory.Options();
options.inJustDecodeBounds = true; // 仅获取图片尺寸
BitmapFactory.decodeFile(filePath, options);
int reqWidth = targetWidth;
int reqHeight = targetHeight;
options.inSampleSize = calculateInSampleSize(options, reqWidth, reqHeight); // 计算采样率
options.inJustDecodeBounds = false;
Bitmap bitmap = BitmapFactory.decodeFile(filePath, options);
```
**缩放处理**​：对解码后的 Bitmap 按 View 尺寸进行精确缩放（避免内存浪费）。
##### 3.内存回收机制
- 监听应用内存状态（`ActivityManager.getMemoryClass()`），在低内存时主动清理内存缓存。
- 与 Activity/Fragment 生命周期绑定（通过 `Lifecycle`组件），在 `onDestroy`时清空与当前页面相关的缓存和任务。

#### 三、缓存策略（提升加载速度与用户体验）
缓存是图片加载框架的核心优化点，需同时考虑内存缓存和磁盘缓存，并处理缓存的读写效率与一致性
##### 1.内存缓存（高频访问）
- ​**快速读写**​：使用 `ConcurrentHashMap`或 `LruCache`（基于双向链表 + `HashMap`，线程安全）。
- **缓存失效**​：支持设置缓存过期时间（如 5 分钟），避免旧图片覆盖新数据。
##### 2.磁盘缓存（持久化）
- ​**存储路径**​：选择 `Context.getCacheDir()`（应用私有目录，无需权限）或 `Environment.getExternalStorageDirectory()`（需适配 Android 10+ 分区存储）。
- ​**异步写入**​：磁盘 IO 是耗时操作，需在子线程执行，避免阻塞主线程。
- ​**缓存清理**​：定期扫描磁盘缓存，删除过期文件（如超过 30 天未访问的文件）。
- ​**唯一键生成**​：确保 Key 唯一（如 `MD5(URL + width + height + transformation)`），避免不同参数的图片覆盖。
##### 3.缓存优先级
- 加载流程：优先检查内存缓存 → 命中则直接显示；未命中则检查磁盘缓存 → 命中则加载到内存并显示；未命中则从网络/本地加载 → 缓存到内存和磁盘。

#### 四、线程与任务调度（保证流畅性）
图片加载涉及网络请求、磁盘 IO、图片解码等耗时操作，需通过线程管理避免阻塞主线程，并优化任务执行顺序。
##### 1.线程池设计
- ​**分类线程池**​：按任务类型划分（如网络任务池、磁盘任务池、解码任务池），避免任务相互抢占资源。
- ​**核心线程数**​：根据设备 CPU 核心数动态调整（如 `Runtime.getRuntime().availableProcessors() + 1`），避免资源浪费。
- **任务优先级**​：支持设置任务优先级（如可见 View 的图片 > 不可见 View 的图片），优先执行高优先级任务。
##### 2.任务调度
- ​**请求去重**​：同一图片的多次请求合并为一个任务（通过缓存 Key 判断），避免重复加载。
- ​**取消无效任务**​：当 View 被回收或页面销毁时，取消对应的加载任务（通过 `Future.cancel()`或标记任务状态）。
- ​**延迟加载**​：对不可见的图片（如 `RecyclerView` 中未滑动的项）延迟加载，优先处理可见区域的图片。

#### 五、图片处理与渲染（保证显示效果）
图片加载的最终目标是正确、高效地显示到 View 上，需处理以下问题：
##### 1.图片变换（Transform）
- **功能扩展**​：支持常见变换（圆角、裁剪、模糊、颜色过滤等），通过 `Canvas`或 `RenderScript`实现（`RenderScript` 性能更优）。
- ​**缓存变换结果**​：对相同变换参数的图片缓存变换后的 Bitmap，避免重复计算。
##### 2.View复用与绑定
- ​**防止错位显示**​：在 `ImageView`被复用（如 `RecyclerView` 滑动）时，取消之前的加载任务，并绑定新的任务到当前 View（通过 `setTag()`标记）。
- ​**生命周期绑定**​：与 Activity/Fragment 的生命周期同步，在 `onPause`时暂停加载，`onResume`时恢复加载。
##### 3.渲染优化
- ​**硬件加速**​：启用 `View.setLayerType(View.LAYER_TYPE_HARDWARE, null)`提升复杂变换的渲染性能（需权衡内存占用）。
- ​**避免重复绘制**​：对已加载的图片，仅在 View 尺寸变化或图片内容变化时重新渲染。

#### 六、兼容性与异常处理（提升稳定性）
Android 设备碎片化严重，框架需兼容不同版本、屏幕尺寸和网络环境。
##### 1.版本兼容
- ​**网络请求**​：Android 9+ 禁用明文 HTTP，需支持 `HTTPS` 或配置 `networkSecurityConfig.xml`。
- ​**文件存储**​：Android 10+ 分区存储限制，本地文件需通过 `ContentResolver`或 `FileProvider`访问。
- ​**Bitmap 回收**​：Android 3.0+ 引入 `Bitmap.recycle()`（谨慎使用，可能导致后续解码失败）。
##### 2.异常处理
- ​**网络异常**​：捕获 `IOException`（如超时、连接失败），支持重试机制（如最多重试 3 次）。
- ​**解码异常**​：处理 `OutOfMemoryError`（如图片过大），降级显示低分辨率预览图或默认占位图。
- ​**IO 异常**​：磁盘读取失败时，跳过缓存并重新加载网络图片。
##### 3.兼容不同屏幕
- ​**多 DPI 支持**​：根据设备 DPI 加载对应分辨率的图片（如 `drawable-hdpi`、`drawable-xhdpi`）。
- ​**动态尺寸适配**​：对同一图片支持多种尺寸缓存（如 `100x100`、`200x200`），避免重复解码。

#### 七、扩展性与自定义（满足多样性需求）
优秀的框架需具备良好的扩展性，允许开发者根据需求定制功能。
##### 1.接口开发
- 提供 `Cache`、`Loader`、`Transformer`等接口，允许替换默认实现（如自定义内存缓存为 `Guava Cache`）。
- 支持自定义线程池、缓存策略、图片变换算法。
##### 2.配置灵活
- 允许通过 `Builder`模式配置全局参数（如内存缓存大小、磁盘缓存路径、默认占位图）。
- 支持针对单个请求的个性化配置（如跳过内存缓存、指定图片尺寸）。
##### 3.监控与调试
- 提供统计功能（如加载耗时、缓存命中率），帮助开发者优化性能。
- 支持调试模式（如显示加载进度、缓存状态），通过 `Stetho`或自定义日志输出。

#### 八、生命周期管理（避免内存泄漏）
图片加载任务需与宿主（Activity/Fragment）的生命周期绑定，防止因任务未取消导致的泄漏。
##### 1.绑定生命周期
- 使用 `LifecycleObserver`监听 `ON_DESTROY`事件，在页面销毁时取消所有关联的加载任务。
- 通过 `WeakReference`持有宿主 Context，避免强引用导致泄漏。
##### 2.任务状态管理
•为每个任务维护状态（如 `PENDING`、`LOADING`、`COMPLETED`），在页面销毁时终止 `LOADING`状态的任务。
