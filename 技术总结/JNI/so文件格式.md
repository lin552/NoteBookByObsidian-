`ELF（Executable and Linkable Format，可执行与可链接格式）`。ELF 是 Linux/Android 系统中二进制文件（包括可执行程序、SO、目标文件 `.o`等）的通用格式，由 `Unix System Laboratories（USL` 设计，后被广泛采用。

#### 一、ELF文件的核心特点
- **跨平台**：支持多种 CPU 架构（x86、ARM、RISC-V 等）和操作系统（Linux、Android、嵌入式系统等）。
- **灵活的分段设计**：通过「段（Segment）」描述文件的加载和执行属性，通过「节区（Section）」描述代码的链接和调试信息。
- **动态链接支持**：SO 作为动态库，ELF 格式中专门设计了「动态段（Dynamic Section）」存储动态链接所需的信息（如依赖库、符号表位置等）。
#### 二、ELF文件的基本结构
一个 ELF 文件（以 SO 为例）的逻辑结构可分为 **4 个主要部分**，从文件头到具体内容依次排列：
```
+-------------------+
|   ELF 头部（ELF Header）       |  // 描述文件整体信息（架构、类型、入口点等）
+-------------------+
|   程序头表（Program Header Table） |  // 描述「段」的信息（哪些段需要加载到内存、加载地址等）
+-------------------+
|   节区（Sections）             |  // 实际的代码、数据、符号表等内容（链接时用）
+-------------------+
|   节区头表（Section Header Table） |  // 描述「节区」的信息（名称、偏移、大小等）
+-------------------+
```
#### 三、ELF头部（ELF Header）:文件的「身份证」
ELF 头部是文件的第一个部分（固定大小，如 64 位 ELF 占 64 字节），用于描述文件的 **基本属性和结构**，操作系统加载文件时会首先读取这部分。
##### 关键字段（以64位ELF为例）

| 字段名                   | 作用                                                                           |
| --------------------- | ---------------------------------------------------------------------------- |
| `e_ident`             | 魔数（前 4 字节固定为 `0x7F 'E' 'L' 'F'`）+ 架构标识（如 ARM64 对应 `ELFCLASS64`）、字节序（小端/大端）等。 |
| `e_type`              | 文件类型：`ET_DYN`表示动态库（SO）、`ET_EXEC`表示可执行程序、`ET_REL`表示目标文件（`.o`）。                |
| `e_machine`           | CPU 架构：`EM_ARM`（32 位 ARM）、`EM_AARCH64`（64 位 ARM）、`EM_X86_64`（64 位 x86）等。     |
| `e_entry`             | 程序入口点（仅可执行程序有效，SO 通常为 0，因为 SO 是被动态加载的）。                                      |
| ``e_phoff`/`e_shoff`` | 程序头表/节区头表在文件中的偏移量（告诉系统从哪里读取这两个表）。                                            |
| ``e_phnum`/`e_shnum`` | 程序头表/节区头表的条目数量（多少个段/节区）。                                                     |
#### 四、程序头表（Program Header Table）:指导「加载」的地图
程序头表（简称「程序头」）是 **操作系统加载 ELF 文件到内存时的依据**，它描述了文件的哪些「段（Segment）」需要被加载到内存、加载到哪个地址、权限（读/写/执行）等。
##### 核心概念：段（Segment）
段是 ELF 文件中 **运行时的最小单位**，多个「节区（Section）」可以被合并到一个段中（例如，多个代码节区合并为「可加载代码段」）。常见的段类型：

| 段类型（p_type） | 作用                                                                        |
| ----------- | ------------------------------------------------------------------------- |
| PT_LOAD     | 可加载段：必须加载到内存的段（如代码段、数据段），操作系统会根据 p_vaddr（虚拟地址）和 p_memsz（内存大小）分配内存并映射文件内容。 |
| PT_DYNAMIC  | 动态段：存储动态链接所需的信息（如依赖的 SO 列表、符号表地址、重定位表位置等），SO 必须包含此段。                      |
| PT_INTERP   | 解释器路径：仅可执行程序有，指定动态链接器路径（如 `/system/bin/linker64`）。                        |
| PT_NOTE     | 注释段：存储额外的元数据（如版权信息、构建信息），加载时可忽略。                                          |
##### 程序头的关键字段（以`PT_LOAD`段为例）
- `p_offset`：段在文件中的起始偏移量（从文件开头算）。
- `p_vaddr`：段在内存中的虚拟地址（操作系统会映射到该地址）。
- `p_filesz`：段在文件中的大小（实际存储的字节数）。
- `p_memsz`：段在内存中的大小（可能大于 `p_filesz`，多出的部分用 0 填充，如 BSS 段）。
- `p_flags`：段的权限（`PF_R`读、`PF_W`写、`PF_X`执行）。

#### 五、节区（Sections）:代码与数据的「容器」
节区是 ELF 文件中 **链接时的基本单位**，用于组织代码、数据、符号表、调试信息等。一个 SO 文件通常包含几十个节区，以下是核心节区：

| 节区名称              | 作用                                                    |
| ----------------- | ----------------------------------------------------- |
| .text             | 代码节区：存储编译后的机器指令（只读、可执行），如函数的实现。                       |
| .data             | 已初始化数据节区：存储已初始化的全局变量/静态变量（可读写）。                       |
| .bss              | 未初始化数据节区：存储未初始化的全局变量/静态变量（运行时初始化为 0，文件中不占空间）。         |
| .rodata           | 只读数据节区：存储字符串常量、const 变量（只读）。                          |
| .dynsym           | 动态符号表：存储 SO 导出的符号（供其他模块调用）和导入的符号（依赖的外部符号，如 `printf`）。 |
| .dynstr           | 动态字符串表：存储 .dynsym中符号的名称（如函数名、变量名）。                    |
| .rel.dyn/.rel.plt | 重定位表：记录需要修正的地址（如 SO 加载到内存后，动态链接器需要根据实际加载地址调整符号引用）。    |
| .hash             | 符号哈希表：加速符号查找（通过哈希快速定位 `.dynsym`中的符号）。                 |
| .shstrtab         | 节区名称字符串表：存储所有节区的名称（如 `.text`、`.data`的字符串）。            |
