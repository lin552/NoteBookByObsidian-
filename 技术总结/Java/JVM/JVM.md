Java 虚拟机（`JVM`）是 Java 技术栈的核心，其考点覆盖**内存管理、类加载机制、垃圾回收、性能调优**等关键领域。以下是基于最新技术趋势和面试高频问题的详细梳理：

#### 一、`JVM`内存模型

##### 1. 内存区域划分​
![[Pasted image 20250323175933.png]]
- ​**线程私有区**​：
    - ​**程序计数器**​：记录当前线程执行的字节码指令地址，线程切换时保存执行位置
    - ​**虚拟机栈**​：存储方法调用的栈帧（局部变量表、操作数栈、动态链接等），与线程生命周期一致
    - ​**本地方法栈**​：为 `JNI（Java Native Interface）`方法服务，与虚拟机栈类似
- ​**线程共享区**​：
    - ​**堆**​：存放对象实例和数组，是垃圾回收的主要区域。可细分为新生代（Eden/Survivor）和老年代
    - ​**方法区**​（元空间）：存储类信息、常量池、静态变量等。`JDK 8` 后使用本地内存实现（元空间），避免永久代内存溢出问题

#### 二、内存问题排查

|问题类型|核心区域|典型触发条件|
|---|---|---|
|内存泄漏|堆、元空间、直接内存|长生命周期对象持有无效引用；动态类未卸载；直接内存未手动释放。|
|内存溢出（OOM）|堆、元空间、虚拟机栈、直接内存|对象总量超过区域容量；递归过深；类元数据爆炸；直接内存分配超限。|
|内存抖动|堆（新生代为主）|短生命周期对象高频创建/回收；Survivor 区/老年代空间不足，触发频繁 GC。|
##### ① 内存泄漏（Memory Leak）
###### 1)Java 堆（Heap）中的内存泄漏
**触发场景**​：
- ​**长生命周期对象持有短生命周期对象的强引用**​：例如，单例对象（生命周期与 `JVM` 一致）持有一个集合（如 `HashMap`），但未及时清理不再使用的对象（如用户会话信息）。
- ​**未正确释放的资源引用**​：如监听器（Listener）、回调（Callback）未显式移除，导致被目标对象长期引用（例如 `EventBus` 注册后未注销）。
- ​**静态集合类的误用**​：静态变量（属于类，生命周期为`JVM` 运行期）直接存储对象，若未主动清理，对象永远无法被回收（如 `static List<Object>` 持续添加元素但无删除逻辑）。

###### 2)方法区（元空间）中的内存泄漏
`JDK8` 后方法区由元空间实现（使用本地内存），主要存储类元数据、常量池、静态变量等。  
​**触发场景**​：
- ​**动态类加载未卸载**​：通过 `ClassLoader` 动态生成大量类（如 `CGLIB` 代理、反射频繁生成类），若父类加载器（如自定义类加载器）未被回收，其加载的类元数据会一直驻留元空间（类卸载条件：类加载器被回收）。
- ​**常量池/静态变量滥用**​：静态变量引用大对象（如大数组），或字符串常量池（`String.intern()`）中累积大量无法回收的字符串。

###### 3)直接内存中的内存泄漏
直接内存通过 `Unsafe.allocateMemory()` 或 `ByteBuffer.allocateDirect()` 分配，需手动调用 `freeMemory()` 释放（或依赖 `PhantomReference` + `ReferenceQueue` 自动回收）。  
​**触发场景**​：
- 未正确释放直接内存：例如，业务代码中分配了直接内存但未调用 `Unsafe.freeMemory()`，导致堆外内存泄漏（不受堆 `GC`管理）。

##### ② 内存溢出（`OOM`,Out Of Memory）
###### 1) 堆溢出（Java heap space）
**触发区域**​：堆。  
​**触发条件**​：对象数量或总大小超过堆的最大容量（`-Xmx`）。  
​**常见场景**​：
- ​**内存泄漏累积**​：如上述静态集合未清理，对象持续累积直至堆满。
- ​**短时间内大量对象创建**​：如循环中创建大对象（如 `byte[]` 数组）且未释放（即使无泄漏，堆容量不足也会 `OOM`）。

###### 2)元空间溢出（`Metaspace`）
**触发区域**​：元空间（`JDK8+`）。  
​**触发条件**​：类元数据、常量、静态变量等占用内存超过 `-XX:MaxMetaspaceSize`（默认无限制，受本地内存约束）。  
​**常见场景**​：
- 动态生成大量类（如 `RPC` 框架动态代理、Spring 注解解析）。
- 加载大量第三方库（如同时引入数百个 JAR 包，类数量爆炸）。

###### 3)虚拟机栈溢出（`StackOverflowError`)
**触发区域**​：虚拟机栈（线程私有）。  
​**触发条件**​：线程请求的栈深度超过虚拟机允许的最大值（`-Xss` 控制单线程栈大小，默认约 `1MB`）。  
​**常见场景**​：
- ​**递归调用过深**​：如无终止条件的递归方法（`void foo() { foo(); }`）。
- ​**超大栈帧**​：方法参数或局部变量过多（如一个方法声明 1000 个 `int` 参数）。

###### 4)直接内存溢出（Direct buffer memory）
**触发区域**​：直接内存。  
​**触发条件**​：直接内存分配量超过 `-XX:MaxDirectMemorySize`（默认等于堆最大容量 `-Xmx`）。  
​**常见场景**​：
- 频繁调用 `ByteBuffer.allocateDirect()` 分配大内存，且未及时回收（如 `NIO` 中大量未释放的 `DirectByteBuffer`）。

##### ③ 内存抖动（Memory Thrashing）
###### ​**触发区域**​：堆（主要是新生代）。
​**触发条件**​：
- ​**短生命周期对象过多**​：对象在 Eden 区创建后，很快变为垃圾（如循环中创建临时对象），导致频繁 `Minor GC`。
- ​**Survivor 区空间不足**​：每次 `Minor GC` 后存活对象超过 Survivor 区容量，触发“动态年龄判定”或直接晋升老年代，导致老年代快速填满，触发 `Full GC`。
- ​**大对象直接进入老年代**​：大对象（如大数组）超过 `-XX:PretenureSizeThreshold` 直接进入老年代，若老年代空间不足，频繁触发 `Full GC`。
