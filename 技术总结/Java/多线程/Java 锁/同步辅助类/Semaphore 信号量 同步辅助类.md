Java 中的 ​**`Semaphore`**​（信号量）是 `java.util.concurrent` 包下的同步辅助类，用于**控制同时访问某个资源的线程数量**，通过“许可证（permits）”机制实现资源的并发访问控制。其核心价值在于**限制资源的并发使用量**，适用于资源池、限流、任务调度等场景。以下是其核心考点的详细梳理：

#### 一、核心功能与设计思想
`Semaphore` 的核心是一个**许可证计数器**​（`state`），初始化时设定可用许可证的数量（`permits`）。线程访问资源前需获取许可证（`acquire()`），访问结束后释放许可证（`release()`）。若许可证已耗尽，线程将被阻塞，直到其他线程释放许可证。

##### **关键特性**​：
- ​**可配置的并发数**​：通过初始化参数 `permits` 设定最大并发线程数。
- ​**许可证管理**​：支持获取（`acquire`）、释放（`release`）、尝试获取（`tryAcquire`）许可证。
- ​**公平性选择**​：支持公平模式（线程按等待顺序获取许可证）和非公平模式（允许插队）。

#### 二、底层实现：基于`AQS`
`Semaphore` 底层通过 ​**`AbstractQueuedSynchronizer (AQS)`**​ 实现同步逻辑，核心依赖 `AQS` 的**状态变量（state）​**和**等待队列**。
##### ​**1. 状态变量（state）​**​
- `state` 表示当前可用的许可证数量（初始化为 `permits`）。
- 获取许可证时，通过 `CAS` 操作递减 `state`（原子性保证线程安全）；释放许可证时，递增 `state`。
##### ​**2. 等待队列**​
- `AQS` 维护一个双向链表（`CLH` 队列变种），用于管理因许可证不足而阻塞的线程。
- 当 `state == 0` 时，新调用 `acquire()` 的线程会被封装为节点并加入队列尾部，然后通过 `park()` 阻塞。

#### 三、关键方法解析
##### 1. `acquire()`：获取许可证（阻塞）​​
- ​**作用**​：当前线程尝试获取 1 张许可证（默认），若许可证不足则阻塞，直到获取成功或被中断。
- ​**实现**​：
    1. 调用 `tryAcquire(-1, TimeUnit.MILLISECONDS)`（超时参数为 `-1` 表示无限等待）。
    2. 若获取失败，将当前线程封装为节点并加入等待队列，调用 `park()` 阻塞。

##### ​2. `acquire(int permits)`：获取指定数量的许可证​
- ​**作用**​：获取 `permits` 张许可证（需 `permits > 0`），若不足则阻塞。
- ​**注意**​：若 `permits` 超过当前可用许可证数，线程会一直阻塞（除非被中断或超时）。

##### ​3. `tryAcquire()`：尝试获取许可证（非阻塞）​​
- ​**作用**​：立即尝试获取 1 张许可证，成功返回 `true`，失败返回 `false`（不阻塞）。
- ​**扩展**​：`tryAcquire(long timeout, TimeUnit unit)` 支持带超时的尝试获取。

##### ​4. `release()`：释放许可证​
- ​**作用**​：释放 1 张许可证（默认），唤醒等待队列中的线程（若有）。
- ​**扩展**​：`release(int permits)` 支持释放指定数量的许可证（需 `permits > 0`）。

#### 四、典型使用场景
##### 1. 资源池限流​
例如：数据库连接池限制同时使用的连接数（如最大 10 个连接）。
```java
public class SemaphoreDemo {
    private static final int MAX_CONN = 10;
    private static Semaphore semaphore = new Semaphore(MAX_CONN);

    public static void main(String[] args) {
        for (int i = 0; i < 20; i++) { // 模拟 20 个线程请求连接
            new Thread(() -> {
                try {
                    semaphore.acquire(); // 获取许可证（连接）
                    System.out.println(Thread.currentThread().getName() + " 获取连接");
                    Thread.sleep(1000); // 模拟使用连接
                } catch (InterruptedException e) {
                    e.printStackTrace();
                } finally {
                    semaphore.release(); // 释放许可证（连接）
                    System.out.println(Thread.currentThread().getName() + " 释放连接");
                }
            }).start();
        }
    }
}
```

##### ​2. 接口限流​
例如：限制同时访问某个 API 的线程数（如每秒最多 100 次请求）。
##### ​3. 任务调度​
例如：限制同时执行的任务数（如线程池中最多 5 个任务并行执行）。

#### 五、公平性与非公平性
##### 1. 公平模式（Fair）​​
- ​**定义**​：线程按等待队列的顺序获取许可证（先等待的线程优先获取）。
- ​**实现**​：构造 `Semaphore` 时传入 `true`（`new Semaphore(permits, true)`）。
- ​**优点**​：避免线程饥饿（所有线程最终能获取许可证）。
- ​**缺点**​：频繁的队列检查增加了开销，吞吐量较低。
##### ​2. 非公平模式（Non-Fair，默认）​​
- ​**定义**​：允许新来的线程插队获取许可证（直接尝试获取，成功则抢占）。
- ​**优点**​：减少线程切换，吞吐量更高（适合竞争激烈的场景）。
- ​**缺点**​：可能导致等待队列中的线程长期无法获取许可证（饥饿）。
#### 六、常用问题与注意事项
##### 1. 许可证必须释放​
- 线程使用完资源后必须调用 `release()` 释放许可证（建议在 `finally` 块中调用），否则许可证会被永久占用，导致其他线程无法获取。

##### ​2. 超时获取的意义​
- `tryAcquire(timeout, unit)` 避免线程无限等待（如接口超时、任务取消），提高系统健壮性。

##### 3. 与 `ReentrantLock` 的区别​

|​**特性**​|​**Semaphore**​|​**ReentrantLock**​|
|---|---|---|
|​**锁类型**​|共享锁（多个线程共享许可证）|独占锁（仅一个线程持有锁）|
|​**并发控制**​|限制最大并发数（`permits`）|互斥访问（同一时间仅一个线程）|
|​**公平性**​|可配置（公平/非公平）|可配置（公平/非公平）|

##### ​4. 与 `CountDownLatch` 的区别​

|​**特性**​|​**Semaphore**​|​**CountDownLatch**​|
|---|---|---|
|​**核心作用**​|限制并发数（许可证）|等待任务完成（计数器归零）|
|​**可重用性**​|可重复获取/释放（许可证循环使用）|一次性（计数器归零后无法重置）|
|​**等待条件**​|等待许可证可用|等待计数器归零|
#### 七、常见面试题
1. ​`Semaphore` 的核心作用是什么？​**​  
    控制同时访问某个资源的线程数量，通过许可证机制实现资源的并发访问控制。
    
2. ​`Semaphore` 如何保证线程安全？​**​  
    底层通过 `AQS` 的 `CAS` 操作（`compareAndSetState`）原子性地更新许可证数量（`state`），确保多线程下的可见性和原子性。
    
3. ​公平模式和非公平模式的区别是什么？如何选择？​**​  
    公平模式按等待顺序分配许可证（避免饥饿），非公平模式允许插队（吞吐量高）。竞争激烈时选公平模式，否则选非公平模式。
    
4. ​`Semaphore` 的 `acquire()` 和 `tryAcquire()` 有什么区别？​**​  
    `acquire()` 阻塞直到获取许可证，`tryAcquire()` 立即返回是否获取成功（不阻塞）。
    
5. ​`Semaphore` 如何实现限流？​**​  
    初始化时设定最大许可证数（如 100），线程访问资源前需获取许可证，超出数量则阻塞，从而限制并发数。
    
6. ​**为什么 `release()` 必须在 `finally` 中调用？​**​  
    确保无论线程是否发生异常，许可证都会被释放，避免资源泄漏（许可证被永久占用）。
