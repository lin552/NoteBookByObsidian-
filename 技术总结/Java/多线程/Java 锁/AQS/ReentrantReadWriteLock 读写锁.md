Java 中的 ​`ReentrantReadWriteLock` 是 `java.util.concurrent.locks` 包下的读写锁实现，支持**读写分离**和**可重入性**，适用于读多写少的并发场景。其核心考点围绕**锁特性**、**实现原理**、**使用场景**及**与 `ReentrantLock` 的对比**展开。以下是详细梳理：

#### 一、核心特性
##### ​1. 读写分离​
- ​**读锁（共享锁）​**​：允许多个线程同时持有读锁，适用于**读操作**​（如缓存读取）。
- ​**写锁（独占锁）​**​：同一时间仅允许一个线程持有写锁，适用于**写操作**​（如数据更新）。
- ​**互斥规则**​：
    - 读锁与写锁互斥：写锁存在时，其他线程无法获取读锁或写锁。
    - 读锁与读锁共享：多个线程可同时获取读锁。
##### ​2. 可重入性​
- ​**读锁重入**​：同一线程可多次获取读锁（需匹配释放次数）。
- ​**写锁重入**​：同一线程可多次获取写锁（需匹配释放次数）。
- ​**锁降级**​：写锁持有者可获取读锁后释放写锁（实现锁降级），但**读锁不能升级为写锁**。
##### ​3. 公平性选择​
- ​**非公平锁（默认）​**​：允许线程插队获取锁，吞吐量更高。
- ​**公平锁**​：按请求顺序分配锁，避免线程饥饿。

#### 二、实现原理（基于`AQS`）
##### 1. 状态变量设计​
- ​**state**​：32 位整数，高 16 位表示**读锁持有次数**，低 16 位表示**写锁持有次数**。
    ```java
    // 获取读锁计数
    static int sharedCount(int c) { return c >>> SHARED_SHIFT; }
    // 获取写锁计数
    static int exclusiveCount(int c) { return c & EXCLUSIVE_MASK; }
    ```

##### ​2. 锁获取与释放​
- ​**读锁获取**​：若无写锁或当前线程持有写锁，允许获取读锁（共享模式）。
- ​**写锁获取**​：需确保无读锁或写锁，且当前线程为写锁持有者（独占模式）。
- ​**锁释放**​：
    - 读锁释放：减少读锁计数，若计数为 0 则唤醒等待队列。
    - 写锁释放：减少写锁计数，若计数为 0 则唤醒等待队列。

##### ​3. 同步队列​
- ​**非公平模式**​：新线程可尝试直接获取锁，失败则加入队列。
- ​**公平模式**​：严格按请求顺序分配锁。

#### 三、使用场景
##### 1. 读多写少​
- ​**缓存系统**​：高频读取缓存数据，低频更新缓存（如商品信息缓存）
- ​**配置管理**​：多线程读取配置，偶尔更新配置（需保证更新时独占性）
##### ​2. 数据统计​
- ​**高频读取统计结果**​（如访问量统计），低频更新统计逻辑。
##### ​3. 数据库连接池​
- ​**读操作**​（获取空闲连接）允许多线程并发，​**写操作**​（扩容/缩容）需独占锁。

#### 四、锁降级与注意事项
##### 1. 锁降级​
- ​**步骤**​：写锁 → 读锁 → 释放写锁。
- ​**作用**​：在修改数据后，通过读锁保证后续读取操作的可见性，避免其他线程修改数据。
    ```java
    writeLock.lock();
    try {
        // 修改数据
        readLock.lock();  // 锁降级
    } finally {
        writeLock.unlock();
    }
    try {
        // 读取修改后的数据
    } finally {
        readLock.unlock();
    }
    ```
##### ​2. 注意事项​
- ​**禁止锁升级**​：持有读锁时无法直接获取写锁，需先释放读锁。
- ​**写锁饥饿**​：非公平模式下，持续读操作可能导致写锁长时间无法获取。
- ​**性能权衡**​：非公平模式吞吐量高，但可能牺牲公平性；公平模式保证顺序，但性能较低。

#### 五、与`ReetrantLock`的对比
| **特性**​    | ​**ReentrantReadWriteLock**​ | ​**ReentrantLock**​ |
| ---------- | ---------------------------- | ------------------- |
| ​**锁类型**​  | 读写分离（共享锁 + 独占锁）              | 独占锁                 |
| ​**并发性能**​ | 读多写少时性能显著提升                  | 所有操作互斥，性能较低         |
| ​**适用场景**​ | 读多写少（如缓存、配置管理）               | 读写均衡或写操作频繁的场景       |
| ​**锁降级**​  | 支持（写锁 → 读锁）                  | 不支持                 |
| ​**锁升级**​  | 不支持（读锁无法升级为写锁）               | 不支持                 |
#### 六、常见面试题
1. ​`ReentrantReadWriteLock` 如何实现读写分离？​**​  
    通过 `AQS` 的 `state` 高 16 位记录读锁计数，低 16 位记录写锁计数，实现读写状态分离

2. ​**锁降级的意义是什么？如何实现？​**​  
    锁降级用于在修改数据后获取读锁，确保后续读取操作的可见性。实现步骤：写锁 → 读锁 → 释放写锁
    
3. ​`ReentrantReadWriteLock` 的公平性如何实现？​**​  
    通过 `AQS` 的同步队列管理线程请求顺序，公平模式下按 FIFO 分配锁，非公平模式下允许插队
    
4. ​**读锁和写锁的重入性如何保证？​**​  
    通过 `state` 计数和线程持有者判断，同一线程可重复获取锁，释放时递减计数
    
5. ​**读写锁的适用场景有哪些？​**​  
    读多写少场景（如缓存、配置管理）、数据统计、数据库连接池等
